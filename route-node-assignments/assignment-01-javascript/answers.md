# Part 2: JavaScript concepts

1. `forEach` calls a callback for each present array element. Its return value is ignored, and `break`/`continue` cannot control the outer iteration. It does not await asynchronous callbacks. Use it for synchronous side effects. `for...of` iterates values of any iterable, supports `break`, `continue`, and sequential `await`; use it when you need that control.
2. Hoisting describes bindings being created before execution. A `var` binding is initialized to `undefined`: `console.log(x); var x = 1;` logs undefined. Function declarations can be called before their declaration. `let` and `const` bindings exist but remain uninitialized until their declaration executes: `console.log(y); let y = 1;` throws ReferenceError. That interval is the Temporal Dead Zone. A function expression follows its variable's initialization rules.
3. `==` may coerce operand types: `5 == '5'` is true. `===` compares without that coercion: `5 === '5'` is false. `null == undefined` is true, but `null === undefined` is false. Prefer strict equality unless coercion is intentional.
4. `try` executes code; `catch` handles thrown errors, and `finally` runs for cleanup. In async functions, await the promise inside try so a rejection is caught: `try { const result = await operation(); } catch (error) { console.error(error.message); }`. A surrounding synchronous try/catch cannot catch a later timer callback's error, or an unawaited rejected promise; attach a rejection handler or handle it within the callback.
5. Explicit conversion is requested by code: `Number('123')` is 123, `String(123)` is '123'. Coercion happens implicitly during an operation: `'5' + 1` becomes '51', while `'5' - 1` becomes 4.
